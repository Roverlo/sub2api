# 本地定制保护

仅在涉及下列功能或上游同步时读取。此清单记录用户已确定的定制方向，不代表所有分支均已包含这些修改。开始时比较当前基线、用户指定的定制分支与目标上游，记录缺失项；不得因本文自动删除/新增功能或把其他未合并分支整体带入任务。

## 已有定制不得被上游回灌

- 部署/运营/合规确认门禁保持禁用：不要恢复登录后的 `AdminComplianceDialog`、`admin-compliance-required`、管理员路由合规状态预取或 `423 ADMIN_COMPLIANCE_ACK_REQUIRED` 拦截。对应已定制的后端 guard 放行、状态返回 `required=false`。
- 订阅入口保持收敛至兑换：`/subscriptions -> /redeem`，`/admin/subscriptions -> /admin/redeem`；按实际路由与侧栏一起检查。
- 优惠码前端注册、邮箱验证及后台管理流程保持下线。验证码更新、Turnstile、腾讯云/阿里云验证码能力可保留，但不得顺带恢复 `promo_code`。
- 已移除的新手引导/onboarding 保持移除。
- 保留兑换码批量复制能力。
- 存在 `deploy/docker-compose.vps04.yml` 的定制分支中，保护其部署差异；该路径不是服务器现状或部署授权，也不能写入私有连接信息。
- 上游可选利润控制/倍率同步等能力默认关闭；用户未明确要求时不启用。

## 同步后的验证

依据本次实际影响检查登录与管理员路由、注册/邮箱 API、侧栏、订阅重定向和兑换批量复制。合规链路修改需覆盖前后端不弹窗、不预取、不返回门禁拦截；后端运行相关 Go 测试，公共服务逻辑必要时运行全套；前端运行 typecheck 与有关行为测试。

部署前备份数据库、当前镜像和实际配置，验证恢复步骤。只升级获准的应用服务；不得为同步应用代码重建 PostgreSQL、Redis 或无关服务。历史分支记录和测试结果不能代替当前分支的验证。
